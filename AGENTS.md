# AGENTS.md

Debian packaging for Calaos-OS (Debian bookworm). Repo: github.com/calaos/pkgdebs.
Most packages wrap a podman container (systemd unit + helper scripts); two are
special: `calaos-meta` (meta package, Debian name `calaos`) and
`calaos-keyring` (APT sources + signing key).

## Layout

- One directory per source package, each with `Makefile`, `debian/`
  (`control`, `rules`, `changelog`, `copyright`, `postinst`, `*.service`) and
  helper scripts (`*_pre`, `start_*`, `*.toml`).
- Dir name (`envoy`, `grafana`, ...) is the build argument; the Debian package
  is in `debian/control` (`envoy` -> `calaos-envoy`, `calaos-meta` -> `calaos`).
- Dirs: calaos-home, calaos-keyring, calaos-meta, calaos-server,
  calaos-web-app, envoy, grafana, haproxy, hue2mqtt, influxdb, mosquitto,
  zigbee2mqtt.
- Root: `Dockerfile` (bookworm builder), `Makefile` (docker wrapper),
  `build_deb` (script run inside the builder), `.github/workflows/`.

## Commands

```
make docker-init                          # build image calaos-os-builder
make build-<dir> PKGVERSION=<v> [IMAGE_SRC=<image>]   # output: pkg/*.deb
make docker-shell
```

Needs docker (container runs `--privileged`). `PKGVERSION` is mandatory.
`build_deb` does `sed -i` on `debian/changelog` and the package `Makefile` in
the working tree and runs `make clean` afterwards: it leaves those files
modified. Do not commit them; run `git diff` / `git checkout -- <dir>` (only
for your own build changes) before committing.

## Verifying a change

No test suite. The check is a build: `make build-<dir> PKGVERSION=0.0.1`
(runs `dpkg-buildpackage` and `lintian`; lintian errors fail the build).
Network is needed: `calaos-keyring` downloads
`https://deb.calaos.fr/calaos/calaos-container/archive.key`, `calaos-web-app`
downloads a GitHub release tarball, `apt-get build-dep` runs inside the image.
Shell scripts can be checked with `bash -n` / `sh -n`.

## Workflow / publishing

- A push or PR does NOT build or publish anything: workflows only have
  `repository_dispatch` (`build_deb`) and `workflow_dispatch`
  (`build_deb_manual.yml`).
- A dispatch builds, creates a GitHub Release `<pkgname>-<version>` with the
  `.deb`, then calls a webhook so the external apt repo refreshes
  (`deb.calaos.fr/calaos/pkgdebs`, configured in
  `calaos-keyring/calaos.list`). Triggering one publishes for real; do not do
  it without being asked.
- The version lives nowhere in the repo; `debian/changelog` keeps the
  placeholder `1.2.3` and `build_deb` substitutes it.

## Gotchas

- New package: add it to the `pkgname` choice list in
  `.github/workflows/build_deb_manual.yml` (it is a hard-coded list) and,
  if needed, to `Depends` in `calaos-meta/debian/control`.
- Keep the `1.2.3` placeholder in `debian/changelog` and the `VERSION?=`
  line in each `Makefile`; `build_deb` greps for those exact strings.
- `build_deb` turns only the first `-` of a version into `~`;
  `calaos-web-app` converts it back to rebuild the upstream tag.
- `postinst` scripts call `pull_calaos_image`, which is not defined here.
  `calaos-container`, `calaos-ddns` and the remote-ui packages (all in
  `calaos-meta` Depends) come from other repositories.
- `container.source` is generated by `make build`, git-ignored, and installed
  to `/usr/share/calaos/<pkg>.source`; units read it via `EnvironmentFile`.
- `.gitignore` also lists directories that do not exist here (calaos-ddns,
  knxd, ola, ...); stale entries.
- Stale text: `make` help mentions `calaos-ddns` and "Arch package".
- Workflows use `actions/checkout@v2` and a third-party release action
  (`meeDamian/github-release@2.0`).
- Comments in files: only the why (user convention).
